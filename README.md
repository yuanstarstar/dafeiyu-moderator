# 大肥鱼 AI 房管（@local/dafeiyu-moderator）

给 DSH 用的 B 站直播间 AI 房管：**同时看弹幕和直播画面**，像真人一样陪聊、接梗、谢礼物；
看到刷屏/广告/引战会先 **@ 本人 温和提醒**，同一个观众提醒够了次数还不改，才 **禁言一会儿**。

- 面板位置：**设置 → AI 房管**　完整介绍（功能、配置项、原理、常见问题）见 [`插件介绍.md`](./插件介绍.md)
- 默认是**演习模式（dryRun）**：所有判断都会记录，但不会真的发弹幕、不会真的禁言。确认效果后再关掉演习、打开「开始上班」。
- 默认**不自动启动**：填好房间号、点「开始上班」才会连直播间。

## 0.1.8：登录也并进来了 —— 插件能自己扫码登录，包里不带任何凭证

以前要用别的插件（`dafeiyu-login-live`）扫码登录、再把凭证文件喂过来。现在插件自己就能登录：

- 面板顶部新增 **「B 站登录」** 卡片：点「生成二维码」→ 手机 B 站扫码 → 自动确认；
  登录成功后如果正在上班，会**自动重连直播间**，不用手动停再开；
- 二维码在插件里画成 SVG（`vendor/node_modules/qrcode`），**只把图片给浏览器，不把登录地址发给第三方**；
- 凭证写在本插件自己的目录：`<插件>/data/bili_credential.json`；
  以前放在 `~/.dsh/bili-duty/bili_credential.json` 的老凭证仍然认（自动兼容，不用搬家）；
- 面板上能看到：当前账号 / UID / 等级 / 凭证文件路径 / 更新时间；「退出登录」会删掉本机凭证并立刻断掉重连；
- **打包不带凭证**：默认 `cookieFile`、`ffmpegPath` 都留空（空 = 走插件自己的 data 目录 / 自动找 ffmpeg），
  发布包里没有 `data/`、没有 cookie、没有任何本机绝对路径。

同时把「独立运行」补齐：

- ffmpeg 自动找：配置 > `PATH` 里的 ffmpeg > `~/.dsh/tools/ffmpeg/bin/ffmpeg.exe`（本机这种）> `<插件>/data/bin` > `<插件>/vendor/ffmpeg`；
- 语音模型自动找：配置 > `<插件>/data/models` > `<插件>/models` > `~/.dsh/speech-to-text/sensevoice/models`；
- 也就是说：把 zip 解到别台机器，装进 DSH，面板里扫码登录 + 填房间号就能跑（语音要自己放 SenseVoice 模型，没有就只做弹幕房管）。

自测：新增 **登录链路 11 项**（没登录时说清楚、凭证路径、出码、状态机 waiting、重复查询、假 key、台账、退出登录），
真起 Python 侧车跑，全程不写本机真凭证。

## 0.1.7：直播间没什么动静时，别自说自话

真机反馈：房间里明明没人说话，它还在自言自语。原因两条：

1. 只要缓冲区里还有（哪怕十分钟前的）弹幕，就被当成「有内容可聊」；提示词又是「说 1 条、别当闷葫芦」，模型于是硬编一句；
2. 「没人说话也兜一句」的兜底同样只看「缓冲区非空」，不看那条消息有多旧。

改法：

- **动静才算数**：弹幕 / 礼物 / 醒目留言 / 进场 / 关注 / 主播语音，都会记一个「最后动静时间」；
  上次说完话之后没有新动静 → 这一轮直接跳过，**连模型都不调**（省 token，也免得它编话）；
- **提示词分两种局面**：有 N 条新动静才要求接话；没有新动静就明确写「别硬找话说，say 给空数组，安静待着」；
- **兜底也要有人说话**：只有最近 2 分钟内确实有人说话，才允许「模型不开口时我兜一句」；
- **静默上限可调**：面板「说话」分组新增 **没人说话超过（秒）就别硬接**，默认 180 秒；
  填 0 = 不限制（想让它在冷场时也偶尔陪一句，就调大或填 0）；
- **面板能看见**：状态卡会写「直播间没新动静，先不开口」/「已经 N 分钟没人说话了，先安静待着」，
  一眼能确认它是在憋着，而不是坏了。

自测：宿主 **104 项**（新增 8 项：没新动静不调模型、不出声、状态写明原因、返回跳过原因、
有新弹幕会接话、静默超过上限不再硬接、两种局面的提示词）。

## 0.1.6：修掉「@ 了两遍」和「主播的弹幕显示两遍」

真机截图里出现过这样一条：

```
@大肥鱼打游戏 @大肥鱼打游戏 活了就好，鱼在呢，晚上陪你慢慢回血
```

原因：发弹幕时我们既给了 `reply_mid`（B 站据此渲染「回复 @某人」），又在正文开头写了 `@昵称`，两处一叠加就成了两个 @。

改法：**正文里不再自己写 @**，只给 `reply_mid`，让 B 站渲染那一个。

- 面板、台账、日志里仍然显示「@昵称 正文」——那是给人看的记录；
- 真正发到直播间的正文是干净的（`say` 会去掉开头的 `@昵称` 再把 `replyMid` 一起发出去，`text`/`sent` 两个字段分开记）；
- 提醒、禁言、回观众点名、回主播，全都走同一条路径，所以不会再有重复。

第二个「显示两遍」是主播自己的弹幕：面板里同一句出现两条（16:38:16 和 16:38:39），
但 `gethistory` 里只有一条 —— 说明是**同一条被宿主收到了两次**：

- 弹幕有两个来源：WebSocket 实时推 + 历史接口每 4 秒补拉（B 站对普通账号的推送有采样，光靠 WS 会漏）；
- 历史接口偶尔很慢（实测 23~40 秒才返回），原来按「到达时间 15 秒内算重复」，
  等它回来时窗口早过了，于是同一条又冒一遍；
- 现在改成按**服务端发送时间**比对（`_already_delivered(uid, text, timeline)`）：
  发送时刻不晚于上次送达就认定同一条，观众真的重发一遍（发送时刻更晚）照常放行；
- 回归测试 `python _test/dedupe.py` 4 项：慢半拍的历史弹幕不再冒、新弹幕能进、
  同一条轮询不重复、真重发仍出现。

自测：**宿主 96 项 + 模型层 4 项 + 侧车去重 4 项 = 104 项**。

## 0.1.5：真正的原因找到了 —— 缺一个会话头，另外给模型更多上下文

0.1.4 那三次「换发法」全都失败，报错是 `收到 1 个块但没有正文（finish×1）`。这个形状说明：**请求根本没发出去**，适配器把底层错误压缩成了一个 `finish` 块，而我当时见到 `finish` 就正常收尾，于是错误被吞掉了。

顺着查下去，原因很具体：

- 这个模型走 `opencode-go`，网关要求每个请求带 `x-opencode-session` 头，**没有就直接 400**（`MissingSessionID`）；
- pi-ai 只有在调用方传了 `sessionId` 时才会加这个头；
- 插件之前没传，于是请求被拒 → 适配器转成 `finish` 错误块 → 我们以为「模型这次没说话」。

0.1.5 的改动：

1. **每次都带 `sessionId`**（插件启动时生成一个稳定的会话 id），请求能正常发出去。
2. **`finish` 块里的真错误不再被吞**：`reason.kind` 是 `error`/`aborted` 时直接抛出里面的 `failure.message`（比如 `Request is missing x-opencode-session`），不再是含糊的「模型返回了空内容」。
3. **「输出额度用完」会换发法重试**：`reason.kind === max-tokens` 时算这次没成，继续按下一套发法问，并把原因记到面板。
4. **给模型更多上下文**：最近动静 14→**30** 条（管控判定 10→20）、主播语音 6→**10** 句、自己说过的话 5→8 句，事件缓冲 40→**160** 条。它现在能看到更完整的一段聊天，接话不会只盯着最后一句。
5. 新增 `_test/llm.mjs`（4 项：finish 错误透传、max-tokens 重试、全空报错、block-end 正文），自测一共 100 项。
## 0.1.4：AI 报错「模型返回了空内容」怎么办

真机日志里看到：模型调用成功了，但**一个字正文都没回来**，于是面板显示「AI 报错：模型返回了空内容」。
这一版不是加一句兜底就完事，而是把「怎么问」也改了：

- **空正文自动换发法重试**：第一次按配置（带 system、带思考参数）；没正常文就退一步「不要思考」；再不行就退到最朴素的纯文本请求。
  三条路里有一条能出字就用它，并且日志里会写第几次成的。
- **报错能看懂**：真全空时，错误会写「试了 3 次都没正文，最近一次：收到 4 个块但没有正文（text-delta×0、reasoning×3、finish×1）」。
  这样一眼能看出是「没发正文」还是「只发了思考」。
- **思考等级可调**：面板「说话」分组新增**模型思考等级**——不思考（最快，推荐）/ 低 / 中 / 高，默认**低**。
  这个模型的思考会先吃掉 token 预算，预算用光正文就是空的；想让它更稳就直接选「不思考」。
- 复盘的 maxTokens 500 → 700、看画面的 220 → 600，同样是为了给正文留地方。

## 0.1.3：为什么它一直不说话（真机反馈：手动能发，自己不出声）

查了现场记录：模型被调用了 12 次，但**每次正文都是空的**。原因是这个模型的思考（reasoning）
会先吃掉 token 预算，预算不够时正文一个字都不给（实测 `max_tokens:60` 时正文 0 字、`finish_reason=length`）。

这一版的修法：

- **模型预算加大**：闲聊 `maxTokens` 600 → **1400**，管控 900；并且「只思考没正文 / 空内容」会直接报错，不再当正常结果吞掉。
- **面板能看见**：状态卡新增三行——`说话：能说 / 说不了 —— 原因`、`最近一轮接话：…`、`模型报错：… / 模型上次回了：…`，一眼知道卡在哪。
- **不再当哑巴**：模型这轮不开口、而且已经 2 分钟没说话时，房管会自己兜一句（每 3 分钟最多一次）；模型报错时也会兜一句，不会静默。
- **刚上班先打招呼**：点「开始上班」6 秒后会说一句「来了来了，我盯着呢」，直接能听到它出声。
- **喊名字立刻回**：以前要等 1 秒 tick + 到点闲聊，现在识别到 @ / 名字就当场回（点名回复不受每分钟配额限制）。

## 0.1.2 修了什么（都是真机反馈）

- **喊它会应**：主播（主人）说话、观众弹幕里 @ 它、提到「大肥鱼 / 肥鱼」，都会优先接一句，并 @ 回对方。
  以前只有直播间的显式命令才认，普通弹幕当耳边风。

- **身份**：默认人设改成网上那条**蓝色大肥鱼**，主播是它的「主人」（见下面「身份」一节）。

## 它怎么工作

```
DSH 宿主（index.js / lib/*.js）
  ├─ Sidecar ── stdio JSONL ──> python/moderator.py
  │       ↑ 弹幕/礼物/SC/进场/在线人数          （bilibili-api-python + 历史弹幕轮询）
  │       └ ffmpeg 抓当前直播画面（FLV 直链抽帧）
  ├─ Brain ── ctx.llm.stream ── 用你当前默认模型做「像人」的决策（可带图片）
  ├─ Vision ── 抓帧 → 附件 → 多模态模型「看懂主播在干嘛」
  ├─ Engine ── 限流、去重、提醒/禁言阶梯、台账、免打扰
  ├─ HTTP  /dafeiyu-moderator/api  ←→ 设置页面板
  └─ Tools  dafeiyu_mod_*  ←→ 对话里直接指挥房管
```

**为什么弹幕要轮询历史接口**：B 站对普通账号的实时弹幕推送是采样的（实测大房间 45 秒 0~1 条），
所以侧车在 WS 之外每 4 秒补拉一次 `dM/gethistory`（带登录 Cookie），两路一起喂给引擎，
保证「看得见弹幕」。礼物 / 上舰 / SC 仍以 WS 为准。

## 面板能干什么

- **B 站登录**：面板顶部扫码登录（二维码、当前账号 / UID / 等级、凭证路径与更新时间、退出登录；登录后自动重连直播间）
- **状态**：连没连上、房间/主播/在线人数、模型、今天说了几句、提醒几次、禁言几次
- **开关**：上班/下班、演习模式、自动说话、画面感知、免打扰时段
- **身份 / 人设**：默认是「网上常见的蓝色大肥鱼」——蓝色的胖鱼、小短鳍当手、腮帮子鼓鼓的；
  主播默认是它的「主人」。可以改名字、物种/形象、外貌、来历、自称、怎么称呼主播、口头禅、补充设定，
  还能决定要不要叫「主人」
- **说话风格**：名字、口吻、口头禅、每分钟上限、最短间隔、最大字数、闲聊间隔、**没人说话超过多久就别硬接**、模型思考等级
- **管控规则**：提醒几次才禁言（默认 2）、统计窗口（30 分钟）、禁言时长（5 分钟）、
  每小时禁言上限（5）、自动解禁、白名单、自定义违禁词、各类违规开关
- **主播语音**：本地识别开关、模型目录、识别间隔、每分钟句数、「喊到我就接一句」
- **现场**：最近弹幕流（含「主播说」）、自己说过的话、当前画面预览、让 AI 描述画面
- **台账**：谁被提醒/禁言过、原因、时间；一键解禁
- **复盘**：让 AI 用真人语气总结刚才这一小时

## 身份（默认：蓝色大肥鱼，主播＝主人）

出厂人设就是网上那条常见的**蓝色大肥鱼**：圆滚滚的蓝身子、肚皮偏浅、两片小短鳍当手、腮帮子鼓鼓的，
一激动鳞片发亮；被主播从网上捞进直播间当房管。它管主播叫**主人**，自称「本鱼」，口头禅「鱼在呢」
「别刷了别刷了」「摸摸鳞片」。

几条写进提示词的硬规矩：

- 不许承认自己是 AI / 大模型 / 机器人；有人问就嬉皮笑脸糊弄（「什么 AI，我是鱼」）
- 被说胖、说丑、说菜：自嘲一句就完事，**不许提醒、不许禁言**
- 主人喊它、问它、跟它说话优先接；主人正说着话别抢话
- 主人自己口嗨、玩梗、骂人**不算违规**；主人让管谁才管谁
- 不替主人许诺（抽奖、改价、加播一律「这我得问主人」）

面板「身份 / 人设」里能改：名字、怎么称呼主播（默认「主人」，取消勾选就直呼其名）、物种/形象、
外貌、来历、自称、口头禅、补充设定。改完点保存，下一句话就按新设定走。

## 行为阶梯（默认值）

1. 第一次违规（刷屏/广告/引战/剧透/辱骂）：**只 @ 提醒**，不进黑名单
2. 30 分钟内被提醒到第 2 次还不改：**禁言 5 分钟**，并记进台账
3. 5 分钟后自动解禁（可关）；同一小时最多禁 5 个人，超了就只提醒
4. 白名单里的 id 永远不动；`dryRun` 模式下所有动作只记录不执行
5. 免打扰时段（默认 03:00–07:00）不主动说话

## 常见问题

- **面板打不开 / 一直转圈**：插件没加载成功，看 DSH 启动日志里 `dafeiyu-moderator` 相关报错。
- **弹幕不进来**：先确认房间在播；WS 是采样的，看 `_test/drive.py` 能不能收到 history 弹幕；
  房间太冷清就是真没弹幕。
- **发弹幕失败**：账号不是该直播间主播/房管、或弹幕被 B 站风控；面板台账里会有 `action ok:false`。
- **抓帧失败**：房间没在播、ffmpeg 路径不对、或网络拿不到 FLV 直链。
- **主播语音一直没字**：多半是 ffmpeg 没认出音轨（B 站偶发，日志里会写「直播流断开（… 0 KB）」）。
  侧车已经会自动换新地址重连；想看 ffmpeg 到底报什么，启动时设
  `$env:DFM_FFMPEG_LOG='D:\tmp\ffmpeg-audio.log'`，重连那次的原始 stderr 会写进去。
- **禁言失败**：需要房管权限；`-101` 一般是没登录/掉登录，`-403` 是没有权限。
- **模型不回复**：默认模型不支持图片时会自动降级成只看文字；`/status` 里能看到模型名。
